# 架构与取舍

## 一套 React 源码，按需分发

69 个组件采用 CSS Module；简单行为使用原生 HTML，复杂交互使用已安装的 Base UI 1.8.0，数据表格使用 TanStack Table 8.21.3。动效使用 CSS 与浏览器能力。

源码复制与 shadcn registry 都从 `registry/ui/` 的同一份文件生成。组件条目只带实现依赖，示例条目带完整可运行示例。主题、工具函数、局部样式和 MIT 许可证随依赖闭包一起交付。

保留原有 core、agent-ui、workspace-ui 三个兼容入口；新增组件使用独立入口。没有 npm 运行时包、多包仓库或同步升级机制。

## 层次

| 层次 | 管理的内容 |
| --- | --- |
| 主题变量 | 颜色语义、字体、圆角、密度；由项目覆盖 |
| 基础组件 | 标签、焦点、选择、禁用、浮层和键盘交互 |
| 组合组件 | 表格、筛选、命令菜单、Agent 状态、文件与工作台展示 |
| 项目适配 | 数据结构、路由、异步请求、权限、持久化与桌面能力 |
| 展示与分发 | 搜索、预览、源码、安装、归档、验证证据 |

项目层把业务数据转换为组件 props，把事件交回业务逻辑。组件没有请求库、全局状态仓库或路由依赖。

## 三类接入

**从零开始：** 选定主题和布局密度，按需复制基础及组合组件，业务逻辑留在项目。

**替换已有 UI：** 先记录原控件的值、事件、校验、禁用、焦点与 Ref 契约。替换单个边界，保留草稿与请求行为，再逐项迁移。新增 API 不能默认兼容原套件。

**复杂项目：** 让新旧组件通过项目适配层共存，逐模块迁移。浮层主题需覆盖 portal 所在范围；项目只保留一套主要交互基元，避免重复包装和冲突的焦点管理。

## 框架范围

| 技术栈 | 共享范围 |
| --- | --- |
| React + Vite / Next.js | 同一份组件源码与 CSS Module；客户端交互保留边界 |
| React renderer + Electron/Tauri | 组件源码可接入；本机桥接和权限由宿主负责，未做真实桌面验收 |
| Vue / Svelte | 可共享视觉 token 与规范，TSX 组件需要对应框架版本 |
| 原生移动端 | 复用设计语义，控件、手势与渲染实现另做 |

SSR 可用组件的静态输出与交互组件的首屏渲染分别验证；不要把事件回调从 Next 服务端跨界传给客户端组件。

## 明确边界

- 文件树用原生 details 与嵌套列表，未实现 ARIA tree 的箭头键模式。
- 分栏通过原生滑块调整，没有拖动分隔线与嵌套分栏。
- 轮播手动切换；不自动播放、不支持手势拖拽。
- 表格是普通分页列表，没有虚拟化、单元格编辑和复杂数据网格。
- 轨道与文字强调用于静态展示；真实数据和动作由项目控制。
- 复制后的源码由目标项目维护，更新时比较改动；共享文件不得静默覆盖。

更多 props 与使用限制在每个组件的网页详情和完整示例中。
